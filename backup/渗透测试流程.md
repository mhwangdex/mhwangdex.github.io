
# 🛡️ 渗透测试全流程指南（适用于 HW / SRC）

## 一、前期准备：目标画像与资产测绘

### 1. 工商信息收集（识别真实攻击面）

**目的**：精准识别目标公司及其关联资产，避免“打偏”。

#### ✅ 收集内容：
- **股权架构**（控股 ≥50% 的子公司视为有效目标）
- **网站 ICP 备案信息**（提取根域名）
- **对外发布产品**：
  - 微信公众号、小程序
  - 移动 App（Android/iOS）
  - IoT 设备、边缘业务系统
- **法人/高管联系方式**（电话、邮箱 → 可用于社工或用户名枚举）

#### 🔍 信息来源：
- 爱企查（AQC）
- 天眼查（TYC）
- 快查（KC）
- 启信宝、小蓝本（部分需手动）

> 💡 **工具推荐**：[ENScan_GO](https://github.com/wgpsec/ENScan_GO)  
> 示例：  
> ```bash
> ./enscan -n "目标公司" -field icp,app,wechat -type aqc,tyc --deep 2
> ```
> 可自动穿透多层子公司，合并导出资产清单。

#### 🎯 应用价值：
1. 扩展攻击面：子公司常存在老旧系统、测试环境、未维护后台。
2. 获取备案域名 → 用于子域名爆破/证书透明日志查询。
3. 法人邮箱 → 构造用户名（如 zhangsan@company.com）用于爆破或钓鱼。

## 二、信息收集阶段（Recon）

### 2.1 域名与网络层信息
- 子域名收集（暴力爆破、证书日志、DNS 聚合）
- IP 段测绘（基于备案、CDN 识别真实 IP）
- CDN 识别与绕过（如 Host 头试探、历史 DNS 记录）
- WHOIS 信息（注册人、邮箱、电话）
- 端口扫描（重点关注常见服务端口）

### 2.2 Web 架构指纹识别
- Web 服务器：Nginx、Apache、IIS
- 中间件：Tomcat、WebLogic、JBoss
- 编程语言/框架：PHP、Java（Spring/Struts）、.NET、ThinkPHP、某 CMS
- 操作系统指纹（基于 HTTP 头、错误页等）

> ⚠️ 若识别出高危组件（如 WebLogic、Struts2），立即进行 **POC 验证**。

## 三、漏洞探测与利用阶段

### 3.1 自动化初筛
- 使用 POC 工具批量探测已知漏洞（如 CVE、历史 RCE）
- 目录扫描（dirsearch、ffuf）→ 寻找：
  - 敏感目录（/admin, /backup, /test）
  - 目录遍历（/static/../../../etc/passwd）
  - 默认文件（robots.txt, .git/, .DS_Store）

### 3.2 功能点深度测试（人工为主）

| 功能模块       | 测试点                                                                 |
|----------------|------------------------------------------------------------------------|
| **搜索框**     | SQL 注入、XSS（反射型）                                               |
| **留言/评论**  | 存储型 XSS（打 Cookie）                                               |
| **登录**       | SQLi、XSS、弱口令、验证码绕过、暴力破解                                |
| **注册**       | SQL 注入、任意账号注册（如 admin@xxx.com）、短信轰炸                   |
| **找回密码**   | 验证码爆破、时间失效、手机号篡改、逻辑绕过                             |
| **个人信息**   | 存储型 XSS、CSRF（修改信息/密码）、越权（平行/垂直，修改 UID 等参数） |
| **文件上传**   | GetShell（解析漏洞、.htaccess、.user.ini）、上传 txt 查看内容         |
| **支付功能**   | 金额篡改、数量绕过、地址 XSS                                          |
| **API 接口**   | 未授权访问、参数篡改、敏感数据泄露                                     |

## 四、重点端口与服务风险清单

| 端口   | 服务        | 风险点                                                                 |
|--------|-------------|------------------------------------------------------------------------|
| 21     | FTP         | 弱口令、匿名登录                                                       |
| 22     | SSH         | 弱口令、CVE-2018-15473（用户枚举）                                     |
| 139/445| SMB         | 弱口令、CVE-2015-0240（RCE）                                           |
| 3389   | RDP         | 弱口令、Shift 后门                                                     |
| 3306   | MySQL       | 弱口令、未授权访问（高版本需认证）                                     |
| 6379   | Redis       | **未授权访问**（可写 SSH 公钥、Webshell）                              |
| 27017  | MongoDB     | 未授权访问、弱口令                                                     |
| 7001   | WebLogic    | 弱口令、T3 协议反序列化、SSRF、WAR 部署 GetShell                      |
| 8080   | Tomcat      | 弱口令（tomcat:tomcat）、管理后台部署                                  |
| 2181   | Zookeeper   | **未授权访问**（泄露节点信息、会话）                                   |
| 11211  | Memcached   | **未授权访问**（可导致缓存投毒、信息泄露）                             |
| 443    | HTTPS       | 心脏滴血（CVE-2014-0160）、弱加密套件                                  |

> 🔒 **原则**：优先测试 **未授权访问** 和 **弱口令** 类问题，成本低、成功率高。

## 五、Top 10 高危漏洞类型（SRC/HW 高频）

1. **SQL 注入**（含布尔盲注、时间盲注）
2. **XSS**（反射型、存储型、DOM 型）
3. **CSRF**（关键操作无 Token/Referer 校验）
4. **SSRF**（内网探测、云元数据泄露）
5. **命令/代码执行**（RCE）
6. **反序列化**（Java/PHP/Python 等）
7. **文件上传漏洞**（GetShell）
8. **越权访问**（水平/垂直）
9. **逻辑漏洞**（支付绕过、短信轰炸、状态篡改）
10. **信息泄露**（.git 泄露、错误堆栈、接口未鉴权）

## 六、渗透原则与技巧

- ✅ **先打“软柿子”**：从子公司、边缘业务、测试环境入手。
- ✅ **业务驱动测试**：理解业务流程才能发现逻辑漏洞。
- ✅ **组合拳攻击**：如“验证码爆破 + 账号密码喷洒”。
- ⚠️ **合规前提**：仅限授权目标，禁止破坏、拖库、影响业务。
- 🧠 **善用工具，但不依赖工具**：自动化覆盖广度，人工挖掘深度。
